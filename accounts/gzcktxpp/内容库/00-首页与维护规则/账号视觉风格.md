# Account Visual Style（账号视觉风格）｜广州出口退税-翩翩

> Account ID: `gzcktxpp`
>
> This file defines the long-term visual DNA for spoken supporting visuals.
>
> 本文件只定义“这个账号怎么看起来”，不定义“这条内容讲什么”。

---

## 1. Visual Positioning（视觉定位）

```yaml
visual_identity:
  core_impression: "出口业务链诊断图：利落、专业、能把货、票、钱、单证放到同一条链上快速找断点"
  audience_feeling: "像一个做过很多退税实务的人，把一笔出口业务拆开后很快指出哪一段没接上"
  differentiation_goal: "与退税小笔记拉开差异：翩翩更像专家诊断台，小笔记更像服务型工作笔记"
```

Visual principle:

> **先把这一笔出口业务完整摆出来，再突出断点。**

---

## 2. Rendering Language（渲染语言）

```yaml
rendering:
  primary: "real export-business objects + clean diagnostic overlay"
  secondary: "semi-realistic trade scene + simplified chain visualization"
  realism_level: "medium-high for goods/documents; medium for relationship graphics"
  allowed_hybrid:
    - "集装箱/货物/单证真实对象 + 关系线"
    - "订单/采购/发票/报关/收汇节点 + 真实贸易场景"
    - "业务链路 + 风险断点高亮"
```

Do not turn the account into:
- pure photography;
- pure infographic;
- character drama.

The signature is the hybrid.

---

## 3. Color System（色彩系统）

```yaml
color:
  primary_colors:
    - "海运青"
    - "冷青蓝"
  secondary_colors:
    - "深海蓝灰"
    - "冷白"
  accent_colors:
    - "珊瑚橙"
    - "亮橙"
  warning_colors:
    - "橙红"
  background_preference: "冷白、浅青灰或深海蓝灰"
  saturation: "中低饱和，异常节点可中高饱和"
  contrast: "中高对比"
```

Color association:
- cyan / teal = export / logistics / international trade;
- coral / orange = diagnosis / break point / important money node.

Avoid generic tax-office blue.

## 4. Graphic Language（图形语言）

```yaml
graphic_language:
  relationship_lines: "清晰链路线，允许分段与断点"
  arrows: "方向明确、路径短"
  cards: "订单、发票、报关、收汇、供应商等业务卡"
  labels: "业务对象短标签"
  icons: "集装箱、单据、账户、供应商、银行、报关等简洁图标"
  highlights: "珊瑚橙断点、节点描边、差异数值"
  borders: "冷灰细边框"
  shadows: "轻"
  depth: "真实对象可有空间感，关系层保持清晰平面"
```

Core chain vocabulary:
- 采购
- 进项
- 出库
- 报关
- 物流
- 收汇
- 申报
- 退税

Do not show all eight every time.

## 5. Composition（构图倾向）

```yaml
composition:
  preferred_layouts:
    - "左到右业务链"
    - "真实货物流 + 抽象资金流双层"
    - "中心订单 + 周边单证节点"
    - "完整链路 + 单一断点"
    - "正常链 vs 异常链对比"
  whitespace: "中等"
  focal_strategy: "断点或不一致项必须成为第一焦点"
  symmetry: "允许非对称，强调诊断方向"
  perspective: "正视关系层 + 真实贸易对象轻透视"
  camera_language: "专业贸易视觉，不做会议室摄影"
```

## 6. Business Object Style（业务对象表现）

```yaml
business_objects:
  documents: "报关单、发票、合同、提单等以真实质感对象卡表示，不依赖小字"
  accounts: "公司账户、个人账户、客户/供应商收付款节点清晰区分"
  money_flow: "青蓝链路 + 珊瑚异常断点，金额可突出"
  goods_flow: "货物、集装箱、港口、仓库作为真实对象"
  process_nodes: "订单、采购、报关、收汇、退税等关键节点"
  risk_markers: "橙红断点、错位、缺口"
  check_markers: "青蓝完成状态或白色勾选"
```

## 7. Human Presence（人物使用）

```yaml
human_presence:
  default_use: "rare"
  maximum_role: "人物不超过画面信息权重的15%"
  preferred_view: "手部翻单证、局部人物、侧身"
  preferred_action: "核对订单/单证，但人物仅辅助业务链"

    - "老板和财务开会"

```

## 10. Preferred Visual Forms（优先示意形式）

```yaml
preferred_visual_forms:
  - "relationship"
  - "process"
  - "comparison"
  - "risk_highlight"
  - "reconciliation"
  - "object_focus"
  - "real_scene_support"
```

Typical fit:
- 货真但资金链断 → comparison + relationship
- 供应商异常 → relationship + risk_highlight
- 报关/收汇金额不一致 → comparison
- 首单退税资料齐但付款异常 → relationship
- 整笔业务捋顺 → reconciliation

## 12. Cross-Account Differentiation（跨账号差异要求）

```yaml
cross_account_differentiation:
  unique_color_signature: "海运青/冷青蓝 + 珊瑚橙"
  unique_rendering_signature: "真实出口业务对象 + 链路诊断覆盖层"
  unique_graphic_signature: "货/票/钱/单证节点 + 明确断点"
  unique_composition_signature: "业务链横向展开，断点成为第一焦点"
```

Must differ from `tsxbj`:
- less paper-note feeling;
- more chain diagnosis;
- more trade/logistics realism;
- stronger diagnostic sharpness.

## 15. Completion Check（完成检查）

- Can the viewer immediately see which part of the export chain matters?
- Does the image contain business meaning beyond a port/container photo?
- Is the key break point visually obvious?
- Does it feel sharper and more diagnostic than `tsxbj`?
- Are people secondary or absent?

# 内容维护说明

本文件只说明内容库的数据流、目录用途和维护边界；具体 Skill 路由由项目根目录 `AGENTS.md` 负责。

## 内容资产流转

原始线索 → 灵感库 → 成熟候选与选题池 → 用户确认 → 正式文案 → 实际发布 → 明确归档 → 历史内容 → 复盘与延展灵感

- `03-选题规划/灵感库/` 保存竞品文案、客户咨询、服务交付、发布反馈、历史延展和覆盖缺口等原始线索。
- [[待发布选题]] 与各业务选题池保存已补全场景和服务关联的成熟候选；它们均为候选资产，而非已发布事实。
- `01-历史内容/` 仅保存实际发布且已明确要求归档的内容，并作为去重与覆盖分析的唯一事实来源。
- `01-历史内容/_history-index.jsonl`、`03-选题规划/_candidate-index.jsonl` 与 `03-选题规划/灵感库/_idea-index.jsonl` 是默认机器检索入口，可从 Markdown 重建。
- `02-内容地图/` 与 `04-内容复盘/` 是按需或周期性重建的派生资产，不是普通选题的默认读取入口，也不能替代历史内容事实。

## 内容库约定

- 一条视频只建立一篇历史笔记，不因多个分类重复保存。
- 历史内容按实际发布日期保存至 01-历史内容/YYYY/YYYY-MM/，分类依赖 Frontmatter 和 wikilink。
- business_line 表示业务板块，theme 表示具体内容主题；固定值以 [[固定选项库]] 为准。
- Frontmatter 仅记录对应资产所需的可检索事实；历史内容格式以 [[历史内容归档规范]] 为唯一规则，灵感笔记字段由灵感录入规则定义。
- 灵感和候选状态统一引用仓库根目录 `shared/schemas/content-state-machine.md`，本文件不另行定义状态枚举。
- 历史记录用于去重和覆盖分析，不作为当前政策有效性的证明；政策、税率、期限、处罚标准和办理流程作为确定性事实或专业结论使用时必须核验当前官方来源，匿名说法可以按公共规则保留为讨论型话题。
- 只有确认实际发布并收到明确归档指令后，才按 [[历史内容归档规范]] 归档。归档强制更新 History Index 和对应候选；派生资产不随每篇归档自动全量重建。

# Account Visual Style（账号视觉风格）｜广州敏哥聊财税

> Account ID: `gzminge`
>
> This file defines the long-term visual DNA for spoken supporting visuals.
>
> 本文件只定义“这个账号怎么看起来”，不定义“这条内容讲什么”。

---

## 1. Visual Positioning（视觉定位）

```yaml
visual_identity:
  core_impression: "电商经营数据诊断台：懂生意、懂钱、懂流水，判断直接、成熟、利落"
  audience_feeling: "像有人把平台、账户、发票、利润和供应商数据摆到同一张经营看板里，迅速指出最影响老板结果的那个点"
  differentiation_goal: "区别于传统财税蓝白宣传图，也区别于轻创业教程风；更像经营后台与财税诊断的混合视觉"
```

Visual principle:

> **先看钱和经营动作，再看专业标签。**

The account should visually communicate:
- owner-side judgment;
- operating consequence;
- data relationship;
- practical diagnosis;
- mature humor through visual contrast, not cartoon jokes.

---

## 2. Rendering Language（渲染语言）

```yaml
rendering:
  primary: "modern business data visualization + realistic business-object hybrid"
  secondary: "semi-realistic e-commerce operating objects, simplified account/payment/document cards"
  realism_level: "medium; objects may be realistic, relationships should be visually abstracted"
  allowed_hybrid:
    - "真实业务物件 + 数据关系覆盖层"
    - "经营后台卡片 + 实物对象"
    - "平台流水/账户/票据的简化示意"
```

Default visual behavior:
- do not rely on people to carry meaning;
- business objects and data relations should dominate;
- use simplified system-like cards, but never imitate real platform or tax interfaces;
- when the topic is highly operational, allow a stronger dashboard / diagnostic-board feeling.

Avoid:
- traditional accounting-office stock photography;
- generic finance brochures;
- overly friendly beginner illustrations;
- heavy government-service aesthetics.

---

## 3. Color System（色彩系统）

```yaml
color:
  primary_colors:
    - "深石墨灰"
    - "炭黑灰"
  secondary_colors:
    - "冷灰"
    - "低饱和米白"
  accent_colors:
    - "暖橙"
    - "琥珀黄"
  warning_colors:
    - "高饱和橙红，仅用于真正异常节点"
  background_preference: "深色或中深色为主，可在高信息密度场景使用浅灰反差卡片"
  saturation: "整体低饱和，强调色中高饱和"
  contrast: "中高对比"
```

Color logic:
- graphite / charcoal = mature business judgment;
- amber / orange = money, action, key variable;
- warning color should be used only for abnormality;
- avoid using blue-gray as the permanent brand base.

---

## 4. Graphic Language（图形语言）

```yaml
graphic_language:
  relationship_lines: "短直线、折线、清晰方向关系；避免装饰性曲线"
  arrows: "简洁、偏粗、方向明确"
  cards: "经营后台式模块卡片，边界清晰"
  labels: "短标签，偏数据项和业务对象名"
  icons: "简洁几何业务图标，不用可爱插画图标"
  highlights: "琥珀/橙色局部高亮、数据框、关键数字聚焦"
  borders: "低对比细边框"
  shadows: "轻微层级阴影，不做玻璃拟态炫技"
  depth: "轻层次感，重点是信息关系而非空间炫技"
```

Recurring visual vocabulary:
- platform order;
- payment flow;
- company account;
- personal account;
- invoice;
- supplier;
- profit / margin;
- cash flow;
- revenue vs declaration;
- upstream / downstream.

---

## 5. Composition（构图倾向）

```yaml
composition:
  preferred_layouts:
    - "中心关键变量 + 周边关联对象"
    - "左右对比"
    - "模块化经营看板"
    - "一条主链路 + 一个异常节点"
  whitespace: "中等留白"
  focal_strategy: "一个关键金额、账户或数据关系必须成为第一视觉焦点"
  symmetry: "允许非对称，强调诊断感和方向性"
  perspective: "正视/轻透视为主"
  camera_language: "信息图式稳定视角，必要时加入真实物件近景"
```

Do not use:
- conference-room compositions;
- two-person face-to-face shots;
- decorative desktop scenes with no information value.

---

## 6. Business Object Style（业务对象表现）

```yaml
business_objects:
  documents: "简化票据/合同卡片，突出关键字段区域而不是大段文字"
  accounts: "清晰区分公司账户、个人账户、平台账户等节点"
  money_flow: "使用方向明确的支付/收款线，金额可作为核心视觉对象"
  goods_flow: "仅在电商/跨境场景需要时出现，不作为默认主体"
  process_nodes: "模块化经营节点，强调因果和前后影响"
  risk_markers: "橙红边框、断点、异常状态块"
  check_markers: "琥珀色或浅亮色勾选/匹配状态"
```

---

## 7. Human Presence（人物使用）

```yaml
human_presence:
  default_use: "rare"
  maximum_role: "人物不超过画面信息权重的20%"
  preferred_view: "手部、侧身、局部人物；必要时完整人物"
  preferred_action: "查看经营数据、核对账户或票据，但动作必须帮助理解"
  avoid:
    - "双人对话"
    - "老板和财务面对面讨论"
    - "泛商务握手"
    - "夸张皱眉/惊讶"
    - "普通职场摆拍"
```

If the same meaning can be expressed with account + payment + invoice relationships, omit the person.

---

## 8. Information Density（信息密度）

```yaml
information_density:
  level: "medium-high"
  max_primary_relations: 1
  max_process_steps: 5
  max_labels: "4–7个短标签"
  visual_scan_target: "1 second"
```

The account can carry more data than the other accounts, but:
- one image still explains one main judgment;
- do not become a complex BI dashboard;
- only show data that changes the owner's understanding.

---

## 9. Text Usage（图内文字）

```yaml
text_usage:
  chinese_text_level: "low"
  short_labels: "允许账户、平台、供应商、收入、成本等2–6字短标签"
  numbers: "鼓励关键金额、比例、利润、流水差异等数字作为视觉焦点"
  typography_feel: "现代经营后台、利落、偏数字化"
```

Exact Chinese sentences should stay in subtitles.

## 10. Preferred Visual Forms（优先示意形式）

```yaml
preferred_visual_forms:
  - "relationship"
  - "comparison"
  - "risk_highlight"
  - "process"
  - "object_focus"
  - "reconciliation"
  - "real_scene_support"
```

Typical account fit:
- 平台流水 vs 申报收入 → comparison
- 个人卡收款 → relationship + risk_highlight
- 票/钱/供应商不一致 → relationship
- 利润被税负吃掉 → comparison / object_focus

## 11. Style-Specific Negative Rules（账号风格反向词）

```yaml
style_negative:
  avoid_rendering:
    - "卡通儿童风"
    - "甜美插画风"
    - "传统蓝白政务宣传风"
    - "纯写实办公室人物摄影作为主体"
  avoid_colors:
    - "大面积标准税务蓝"
    - "粉色甜系"
    - "彩虹多色"
  avoid_layouts:
    - "PPT三栏模板"
    - "满屏小卡片"
    - "人物占据画面中心"
  avoid_materials:
    - "廉价塑料3D"
    - "过度玻璃拟态"
  avoid_effects:
    - "霓虹赛博朋克"
    - "复杂HUD"
    - "夸张红色警报"
  avoid_people_style:
    - "夸张职场表演"
    - "双人讨论"
  other:
    - "泛财税宣传海报感"
    - "无业务对象的抽象科技背景"
```

## 12. Cross-Account Differentiation（跨账号差异要求）

```yaml
cross_account_differentiation:
  unique_color_signature: "深石墨/炭灰 + 暖橙/琥珀"
  unique_rendering_signature: "经营数据诊断台 + 真实业务对象混合"
  unique_graphic_signature: "数据卡片、账户节点、金额高亮、经营关系线"
  unique_composition_signature: "关键变量居中，周边业务数据围绕"
```

The visual identity should immediately feel closer to:
> **老板经营后台 / 数据诊断**
than:
> 财税宣传页 / 创业教程 / 出口单证流程图.

---

## 13. Visual Flexibility Boundary（风格弹性边界）

```yaml
flexibility:
  can_change:
    - "数据卡片多少"
    - "真实物件比例"
    - "关系图或对比图"
    - "浅色或深色局部模块"
  must_remain_stable:
    - "深石墨+暖橙的色彩逻辑"
    - "经营诊断感"
    - "金额/账户/流水为优先视觉对象"
    - "人物低占比"
    - "直接、利落的信息层级"
```

---

## 14. Priority Rule（优先级）

```text
信息准确
>
当前经营问题
>
最适合的视觉解释形式
>
账号经营诊断视觉DNA
>
装饰效果
```

If a dashboard-like style makes the current topic harder to understand, simplify it.

---

## 15. Completion Check（完成检查）

- Visual first impression feels like business diagnosis, not generic tax.
- Money / account / platform / invoice relationships are easy to scan.
- The style does not resemble gzXZCS beginner-friendly tutorial visuals.
- The style does not resemble qycslc strategic equity diagrams.
- Human dialogue is not the default.
- Orange/amber is used for judgment and action, not decoration.

# Account Visual Style（账号视觉风格）｜企业财税-老陈

> Account ID: `qycslc`
>
> This file defines the long-term visual DNA for spoken supporting visuals.
>
> 本文件只定义“这个账号怎么看起来”，不定义“这条内容讲什么”。

---

## 1. Visual Positioning（视觉定位）

```yaml
visual_identity:
  core_impression: "企业决策沙盘：稳重、老练、结构清楚，能把股权、控制权和未来变化放在同一张图里"
  audience_feeling: "像一个资深顾问把今天的决定和未来两三步的变化提前画出来"
  differentiation_goal: "区别于基础财税教程和快速风险诊断；视觉更成熟、更安静、更有长期决策感"
```

Visual principle:

> **先答眼前，再把以后会发生什么画出来。**

---

## 2. Rendering Language（渲染语言）

```yaml
rendering:
  primary: "premium strategic business diagram + editorial consulting visual"
  secondary: "subtle realistic company/equity objects, restrained document-object hybrid"
  realism_level: "medium-low; structure over photography"
  allowed_hybrid:
    - "股权节点 + 比例 + 时间轴"
    - "企业结构图 + 少量真实业务物件"
    - "融资前后变化示意"
```

The visual should feel:
- strategic;
- mature;
- calm;
- high-trust;
- board-level without becoming a boardroom photo.

---

## 3. Color System（色彩系统）

```yaml
color:
  primary_colors:
    - "深墨绿"
    - "深灰绿"
  secondary_colors:
    - "象牙白"
    - "暖灰"
  accent_colors:
    - "沙金"
    - "铜金"
  warning_colors:
    - "深砖红或暗铜红，仅用于关键风险"
  background_preference: "象牙白或深墨绿，按内容选择"
  saturation: "低饱和"
  contrast: "中等偏低，关键节点局部提高"
```

Avoid flashy finance colors.

---

## 4. Graphic Language（图形语言）

```yaml
graphic_language:
  relationship_lines: "稳定直线/树状连接，线条偏细"
  arrows: "少量、克制、方向明确"
  cards: "矩形或轻圆角咨询卡"
  labels: "短、正式、少量"
  icons: "极简几何、企业/股东/资金节点"
  highlights: "沙金描边、节点放大、比例高亮"
  borders: "细线、低对比"
  shadows: "非常轻"
  depth: "以层级和结构深度为主，不依赖3D空间"
```

Key visual objects:
- 股东;
- 公司;
- 控制权;
- 股权比例;
- 融资前后;
- 新股东进入;
- 核心员工;
- 退出;
- 股权转让;
- 资金与税;
- 时间变化.

---

## 5. Composition（构图倾向）

```yaml
composition:
  preferred_layouts:
    - "股权树 / 控制结构"
    - "融资前后双阶段"
    - "时间轴 + 比例变化"
    - "中心公司 + 股东节点"
    - "一项决定 → 两三步后果"
  whitespace: "较多"
  focal_strategy: "核心比例、控制节点或未来变化作为唯一焦点"
  symmetry: "偏稳定、平衡"
  perspective: "正视、平面结构"
  camera_language: "咨询报告式清晰结构，不用拍摄感主导"
```

## 6. Business Object Style（业务对象表现）

```yaml
business_objects:
  documents: "股东协议、章程、交易文件用简化卡片表示"
  accounts: "仅在资金与股权判断相关时出现"
  money_flow: "细线资金路径，少量金额"
  goods_flow: "通常不使用"
  process_nodes: "股东/公司/融资/退出等决策节点"
  risk_markers: "暗铜红节点、断裂关系、未来冲突点"
  check_markers: "沙金/深绿确认节点"
```

---

## 7. Human Presence（人物使用）

```yaml
human_presence:
  default_use: "rare"
  maximum_role: "人物不超过画面信息权重的15%"
  preferred_view: "手部、背影、局部；通常无需人物"
  preferred_action: "必要时用于签署、讨论股权文件，但不得成为主体"
  avoid:
    - "会议室多人讨论"
    - "商务握手"
    - "成功人士肖像"
    - "夸张冲突"
    - "年轻互联网创业鸡血画面"
```

The account's authority should come from structure, not people.

---

## 8. Information Density（信息密度）

```yaml
information_density:
  level: "medium"
  max_primary_relations: 1
  max_process_steps: 5
  max_labels: "4–6个"
  visual_scan_target: "1 second"
```

Allow slightly more structural complexity, but do not create full legal/equity diagrams.

## 10. Preferred Visual Forms（优先示意形式）

```yaml
preferred_visual_forms:
  - "relationship"
  - "comparison"
  - "process"
  - "reconciliation"
  - "object_focus"
  - "risk_highlight"
  - "real_scene_support"
```

Typical fit:
- 50:50谁拍板 → relationship
- 融资前后比例 → comparison
- 员工股权退出 → process
- 股权转让只看税不看控制 → relationship + comparison

---

## 15. Completion Check（完成检查）

- The image feels calm and strategic.
- Today's choice and future consequence can be seen clearly.
- It does not look like a basic registration tutorial.
- It does not look like a fast risk-alert dashboard.
- Authority comes from structure and proportion, not elite-person imagery.

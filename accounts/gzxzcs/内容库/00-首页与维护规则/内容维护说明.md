# 内容维护说明

本文件只保留内容资产的项目级约定。任务路由由项目级 `AGENTS.md` 和 `.codex/agents/video-account-operator.toml` 负责；具体执行由对应的独立 Skill 负责。

## 内容资产流转

原始线索 → [[选题灵感收集]] → [[待发布选题]] 或业务选题池 → 用户确认 → 文案 → 实际发布 → 明确归档 → 历史内容与灵感回流

- [[选题灵感收集]] 保存竞品文案、客户咨询、服务交付、发布反馈、历史延展和覆盖缺口等原始线索。
- [[待发布选题]] 与各业务选题池保存已补全场景和服务关联的成熟候选。
- `01-历史内容` 仅保存实际发布且已明确要求归档的内容，并作为去重与覆盖分析的唯一事实来源。
- 三个 JSONL Index 是默认机器检索入口，可从 Markdown 重建；内容地图、缺口、重复检查和复盘是按需或周期性重建的派生资产。
- 选题不使用热点 API，不按早中晚分配；每次由用户需求触发，输出 5 个方案。

## 内容库约定

- 一条视频只建立一篇历史笔记，不因多个分类重复保存。
- 历史内容按实际发布日期保存至 `01-历史内容/YYYY/YYYY-MM/`，分类依赖 Frontmatter 和 wikilink。
- `business_line` 表示业务板块，`theme` 表示具体内容主题；固定值以 [[固定选项库]] 为准。
- 灵感和候选状态统一引用仓库根目录 `shared/schemas/content-state-machine.md`，本文件不另行定义状态枚举。
- 历史记录用于去重和覆盖分析，不作为当前政策有效性的证明；政策、税率、期限、处罚和办理流程必须核验当前官方来源。
- 只有确认实际发布并收到明确归档指令后，才按 [[历史内容归档规范]] 归档。归档强制更新 History Index 和对应候选；派生资产不随每篇归档自动全量重建。

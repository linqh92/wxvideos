# 内容维护说明

本文件仅保留内容资产维护约定。任务路由由仓库根目录 `AGENTS.md` 负责；具体执行分别由 `idea-intake`、`topic-planning`、`text-broadcast-copywriting`、`spoken-copywriting`、`publish-archive` 公共 Skill 负责。历史读取规则见仓库根目录 `.codex/skills/topic-planning/references/history-vault-rules.md`。

- 一条已发布视频只建立一篇历史笔记，不因多个分类复制。
- 历史内容按实际发布日期保存到 `01-历史内容/YYYY/YYYY-MM/`；分类依赖 Frontmatter 和 wikilink。
- `business_line` 表示服务板块，`theme` 表示具体主题；固定值以 [[固定选项库]] 为准。
- 选题的目标客户与经营场景以 [[账号基本定位]] 为准：优先创业筹备期的股权设计，以及快速发展期的股东架构调整；成熟企业、家族传承和存量重组不作为新增选题主线。
- 内容资产按“原始线索 → 灵感库 → 待发布选题或业务选题池 → 用户确认 → 文案 → 实际发布 → 明确归档 → 历史内容与灵感回流”流转。
- [[选题灵感收集]] 只作独立录入索引；灵感、竞品数据或热点仅能作为参考，不能替代历史避重、服务关联和事实核验。
- [[待发布选题]] 与各业务选题池只保存已补全场景和服务关联的成熟候选；候选需使用统一候选卡字段。
- 三个 JSONL Index 是默认机器检索入口，可从 Markdown 重建；内容地图、缺口、重复检查和复盘是按需或周期性重建的派生资产。
- 灵感和候选状态统一引用仓库根目录 `shared/schemas/content-state-machine.md`，本文件不另行定义状态枚举。
- 只有“实际发布”且“明确归档/写入”同时满足，才按 [[历史内容归档规范]] 写入历史库；归档强制更新 History Index 和对应候选，派生资产不随每篇归档自动全量重建。
- 历史笔记只用于去重和覆盖分析，不能证明当前政策仍有效；公司法、税法、登记、申报、税率、期限或处罚标准作为确定性事实或专业结论使用时必须核验官方来源，匿名说法可以按公共规则保留为讨论型话题。

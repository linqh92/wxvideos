# 历史内容归档规范

本文件是本项目发布后历史内容归档的唯一格式规范。

## 归档触发条件

只有同时满足以下条件，才可以写入历史库：

1. 用户已明确说明内容实际发布或已更新完成。
2. 用户明确要求“确认写入知识库”“确认归档”或等价指令。
3. 能够唯一确定实际采用的标题、正文和发布日期。

只确认了选题或文案的内容，不得直接写入历史库；未发布内容保留在 `03-选题规划`。确认选题或文案均不等于实际发布。

## 文件位置与命名

- 目录：`内容库/01-历史内容/YYYY/YYYY-MM/`
- 文件名：`YYYY-MM-DD｜内容标题.md`
- 一条视频只建立一篇笔记；写入前检查同名或疑似重复笔记，禁止覆盖。

## Frontmatter 固定字段

归档笔记必须包含以下字段：

- `title`
- `status`
- `publish_date`
- `business_line`
- `theme`
- `content_type`
- `content_format`
- `audience`
- `pain_scene`
- `content_goal`
- `region`
- `platform`
- `series`
- `source`

字段要求：

- `title` 必须与实际发布标题一致。
- `publish_date` 使用实际发布日期，不使用归档操作日期替代。
- `business_line`、`theme`、`content_type`、`audience` 优先采用 [[固定选项库]] 中的固定值。
- `content_format` 记录实际发布载体，只允许 `text_broadcast` 或 `spoken`；不得用候选的 `recommended_format` 直接代替。
- `pain_scene` 只写一个主要客户场景，避免堆叠多个痛点。
- `content_goal` 写知识库可追踪的内容目标，不写宣传口号。
- `region` 与 `platform` 使用本项目既定值；除非项目规则发生变化，不得因归档操作临时更改。

## 正文固定结构

```markdown
# 内容标题

## 内容概述

用 2—4 句说明这条内容讨论什么、解决什么判断问题，以及内容边界。

## 目标客户

说明具体客户类型、所处企业阶段或业务状态。

## 目标客户痛点场景

用一段话描述客户在什么情况下遇到什么困难，以及为什么需要这条内容。

## 内容正文

保留实际发布的完整正文，按原发布顺序记录，不改写事实，不补充未发布内容。

## 可延展选题

- 延展选题 1
- 延展选题 2

## 关联内容

- 暂无直接关联内容
```

### 编写边界

- 不写“风险评估”。风险检查属于文案制作阶段，不属于历史内容知识沉淀。
- 不写“一句话总结”或“一句话结论”。需要概括时使用“内容概述”，写成 2—4 句。
- 不重复保存 3 个标题方案、备用标题或创作过程；只保留实际采用的标题。
- 不输出镜头、画面、字体、版式等制作信息。
- 不编造发布数据、客户反馈、政策结论或案例。

## 可延展选题规则

- 每篇保留 1—3 个与原内容直接相关、但不重复原结论的后续题目。
- 延展题目必须能对应业务方向、客户场景或服务机会。
- 如果暂时没有可靠延展题目，填写“待根据发布后咨询问题补充”，不得凭空扩展。

## 关联内容规则

- 只关联历史库中已存在、主题或客户场景有直接关系的笔记。
- 使用 Obsidian wikilink：`[[文件标题]]`，显示文字与目标文件标题一致。
- 关联内容按“前置主题 → 当前主题 → 后续主题”或“同一客户场景”排列。
- 没有相关内容时填写“暂无直接关联内容”，不得制造链接。

## 归档完成检查

- [ ] 已确认实际发布标题、正文和日期。
- [ ] 文件路径和文件名符合规范。
- [ ] Frontmatter 字段完整，固定选项没有混用同义词。
- [ ] `content_format` 已按实际发布载体写为 `text_broadcast` 或 `spoken`。
- [ ] 正文包含内容概述、目标客户、目标客户痛点场景、内容正文、可延展选题、关联内容。
- [ ] 未写入风险评估、一句话总结、备用标题和未发布信息。
- [ ] 没有同名或疑似重复笔记。
- [ ] `_history-index.jsonl` 已增量更新，关联候选已按公共状态机更新；内容地图、月度复盘和缺口分析仅在明确要求时重建。
- [ ] 有可靠延展问题、评论或咨询反馈时，已按“一条一篇”回流灵感库并增量更新 `_idea-index.jsonl`。

历史旧笔记允许缺少 `content_format`，不得根据篇幅、文风或候选建议批量猜测回填。

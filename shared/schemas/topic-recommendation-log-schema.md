# 选题推荐与反馈记录

## 用途与位置

记录当前账号实际推荐和用户反馈，供跨次选题避重与调整使用。它是独立事实源，不是候选索引，不属于内容状态机，也不能从候选或历史重建。

路径：`accounts/{CURRENT_ACCOUNT}/内容库/03-选题规划/推荐记录/YYYY-MM.jsonl`。按事件时间所在月份保存，一行一个 JSON 对象，UTF-8。首次实际推荐才创建；不存在表示尚无记录，不阻塞选题。既有文件无法解析时不得覆盖，说明无法可靠恢复反馈记忆，先修复或依用户指示继续。

## 事件字段

每个事件必需：`event_id`（唯一 UUID）、`event_type`、`occurred_at`（带时区的 ISO 时间）、`account_id`（当前账号）。同一逻辑事件重试复用 ID，已存在则不重复 append。写入前核对账号、已有 ID 与 JSON 可解析性，写入后读回核对；失败必须说明未保存，不宣称跨次记忆已生效。

### recommendation：实际推荐批次

- `batch_id`：唯一批次 ID；局部换题生成新批次。
- `replaces_topic_ids`：局部换题时填写被替换题的 ID，其他情况为空数组；以此保留原批次未替换项，不能把局部批次当成整轮选择范围。
- `request_summary`：本轮业务重点、范围和有效偏好，不添加推测。
- `topics`：实际交付的选题数组，每项包含：
  - `topic_id`：首次推荐分配稳定 UUID；同一实质选题再次推荐复用，不能通过改标题绕过反馈。
  - `title`、`audience`、`decision_question`、`core_answer`、`key_conditions`、`service`。
  - `demand_basis`：来源类型、引用路径或本次材料说明；行业推演写明“待验证需求假设”，不冒充真实咨询。
  - `recommended_format`：`text_broadcast`、`spoken` 或 `either`。
  - `source_refs`：已有候选、灵感、历史或核验来源引用；无则空数组。
- `return_reason`：首次推荐为空；旧题回归写具体新增依据或用户请求。

### feedback：用户选题反馈

- `batch_id`：关联批次；跨批次方向反馈可为空。
- `topic_ids`：明确涉及的题目；方向反馈可为空数组。
- `scope`：`topic`、`batch` 或 `direction`。
- `signal`：`selected`、`skip`、`reject`、`preference` 或 `reinstate`；这是交互标签，不是候选状态。
- `user_text`：保留支持本条判断的用户原话。
- `scope_description`：明确题目或方向范围，不扩大否定。

“选 C”只记录 C 的 selected，不伪造用户拒绝 A/B/D/E；“换一批”记录该批 skip；“这题不要”记录题目 reject；“这个方向不要”记录方向 reject；“太泛”记录相应 preference。歧义反馈先按能确定的范围应用，必要时澄清，不推断永久偏好。用户改变主意时 append 新反馈，不改写旧事实。

同一轮明确采用多个彼此独立的题目时，每个题目分别 append 一条 `selected` feedback：各自使用唯一 `event_id`，`topic_ids` 只包含当前一个题目，`batch_id` 相同，并在每条事件中保留同一用户原话、用 `scope_description` 指明当前题目。不得改成 `scope: batch`，也不得因用户选择其中多个而把其余未提及题目记录为 skip 或 reject。“有意向”“先留着”等未明确进入生产的表达不记录为 selected；无法判断分别制作还是合并时先澄清。

## 下一轮如何使用

具体读取与增量维护遵循 `shared/rules/topic-memory-reading.md`：近期 5 批＋有效偏好摘要＋旧推荐按需检索。`_preferences.json` 与 `_retrieval.sqlite` 为可重建派生资产，月度原始日志仍是事实源。推荐或反馈追加后同步缓存，反馈后增量维护摘要；普通轮次不扫描并输出所有日志。

读取历史推荐的紧凑字段和反馈，按实际时间解释，正文按需读取。最近批次中未被选择的题默认退出下一轮；沉默只意味着无反馈，不得记录成拒绝。更早的推荐也不能因时间过去或状态仍可推荐而自动回归。

按客户决策问题和核心答案进行语义比对，而非只比标题或 ID。同一服务可以有不同的新问题。旧题回归需用户主动指定，或新材料、新条件、新判断价值，并明确回归理由；重复保存同一素材不是新依据。明确 reject 的题目或方向，只有用户明确恢复或调整该范围后才重新推荐，新材料不能自行覆盖否定。

新请求明确选择某一已否定方向时，只在该请求范围内恢复。换掉一题只作用于该题，其余已选和保留项不因新批次被误判为跳过。选题反馈只改变推荐判断，不擅自修改候选卡或灵感状态。

## 效果回流

用户明确要求记录或复盘发布效果时，可 append `performance` 事件：关联 `topic_ids`、`history_path`、`observation_window`、`source`、`results`（用户实际提供的曝光、有效咨询、进一步沟通等）与 `attribution_limits`。未知数据缺省，不填零；无法确认关联时保留未知，不猜测归因。有效咨询指符合当前账号业务范围、围绕具体业务问题的咨询；播放点赞仅作辅助。

后续选题按需读取相关效果摘要，不默认扫描完整复盘。自动历史延展属于内容推演，不能当成真实客户反馈。

# 中文口播表达

## 适用范围

本文件用于 `CONTENT_FORMAT=spoken` 的说话生成与编辑。获客目标、事实边界、账号身份和编导流程由口播 Skill 与公共规则定义。

This reference applies ONLY to `spoken-copywriting` and MUST NOT be inherited by `text-broadcast-copywriting`.

## 说话情境

依据当前角色与客户关系生成自然简体中文。先知道这位客户为什么关心、出镜者想说明什么，再选择本题的句子。直接写成说话，听众应在不看字幕的情况下理解。

说话单元可以是一句判断、一段解释、半句补充、自然提问或条件说明。长短和语法形态随意思变化；语气词、省略、轻微自我修正按人物与情境使用。句长、问句、幽默和语气词均无配额。

对象清楚比句子短更重要。专业名词需要时准确使用，并说明对客户有什么影响。代词不明确时重复对象；重复承载强调、情绪或听觉澄清功能时可以保留。

前后关系听得懂时直接承接，需要解释转折或因果时使用自然连接。收尾停在本题的有用判断、结果或真实服务需求上。

## 角色资料的使用

账号行为模型描述判断倾向，例句描述态度和节奏，业务词列举描述适用范围。它们均不提供可直接填入正文的段落、词组或步骤。

本题只调用有用的角色特征。角色的专业知识可以参与内部判断；正文中每个业务对象、条件和操作建议都应能解释为什么与这个问题有关。

## 信息取舍与反罗列

专业判断可以在内部检查完整链路，口播正文只说听众理解当前结论所需的最短主线。事实库存、条件库存和资料库存都不是口播提纲，不得按输入顺序逐项转写。

出现以下情况时默认重写，除非本题明确就是清单、盘点、分类比较或逐步操作：

- 一句话连续出现四个及以上并列业务对象，听众难以判断哪个最重要；
- 同一句同时罗列“要准备什么”和“按什么维度处理”等两套清单；
- 连续两段都靠资料名、环节名或检查问题展示专业度；
- `放在一起核对`、`完整顺一遍`、`逐项对应起来`、`这几个都要看` 等概括动作代替了当前真正要说明的判断；
- 删除其中若干名词不影响结论，但仍为了显得完整而保留。

修复时依次选择更自然的表达：先留下会改变结论的关系；需要举例时使用一个核心对象加一两个代表性例子；需要多个条件时改成听得懂的分支；仍然过载时缩小本篇问题。不要只把长串名词拆成多个同样密集的短句。

完成后做一次不看文字的朗读判断：如果一句话需要明显憋气、听完只能记住资料很多却记不住要判断什么，或说话人很难自然重读重点，就继续压缩或改写。数字计算、明确清单和必要法定条件可按内容需要例外，但仍应分层，让听众知道主次。

## 跨稿件表达检查

先根据本题独立完成初稿，再比对当前对话中同一账号最近的至多三篇已完成口播。样本不足时，可读取当前账号 `01-历史内容/_history-index.jsonl`，按发布时间选择明确标记 `content_format=spoken` 的近期记录，合计最多读取三篇正文。历史稿只用于识别重复和惯性，不提供当前稿件的句法、词组或信息顺序范本。

索引路径相对仓库根目录解析，读取前确认仍位于 `accounts/{CURRENT_ACCOUNT}/内容库/`。历史 Markdown 是正文事实源。无索引、无口播记录或无可用正文时跳过历史比对，检查当前草稿与角色资料的表达依赖；不得声称完成了跨稿件验证。旧记录缺少载体字段时不猜测。

比对关注：

- 开场、转折、收尾是否重复相同句法和信息释放顺序；
- 关键词组合是否跨无关选题惯性出现；
- 是否将同一组专业对象或检查步骤搬入新问题；
- 是否沿用例句，仅替换名词、数字或同义词。

如果最近三篇中至少两篇已经使用长串对象、完整业务链、连续检查问题或相同的概括动作，把该结构视为本篇的负面重复信号；除非当前题目本身要求清单，否则从当前结论重新组织。判断重复是否必要：同一专业名词、连续专题的明确对象和有听觉作用的重复可以保留；缺少本题理由的重复，从当前客户疑问与事实关系重新组织。变化来自问题差异，避免为了区别而硬换开场、强加幽默或改变事实结论。

## 编辑标准

朗读检查重点是客户能否听懂、愿意听、相信这个人的判断。书面抽象表达改为能理解的对象与动作，歧义补清，冗余删去。

判断句子的价值时同时考虑信息、停留、情绪、人物关系、信任与咨询意愿。有作用的人物观察和自然承接可以保留。发现问题后针对性修改，保留已成立的表达。

同时检查当前稿件的信息推进方式。认知纠偏应来自本题确实存在、并会影响客户行动的误解；如果一个要点不需要先否定客户也能成立，就顺着结果、原因、条件、比较、步骤或动作直接说明。避免为了显得有判断而反复把客户放在被纠正的位置，具体取舍仍由当前角色、客户关系和题目决定。

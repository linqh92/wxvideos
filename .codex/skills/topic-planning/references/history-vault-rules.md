# 历史内容库读取规则

## 动态位置

```text
内容库：accounts/{CURRENT_ACCOUNT}/内容库
历史事实源：01-历史内容/**/*.md
历史检索层：01-历史内容/_history-index.jsonl
候选检索层：03-选题规划/_candidate-index.jsonl
灵感检索层：03-选题规划/灵感库/_idea-index.jsonl
```

只允许读取根 `AGENTS.md` 已锁定的当前账号。

## Shortlist First, History Check Second

继续采用 Metadata First、Body On Demand；索引在本地筛选与全量输出到模型上下文是两回事。普通选题必须先依据账号业务、客户经营动作、实际影响和服务承接形成初步候选，再使用历史检索。历史是审核材料，不是默认选题入口。

普通选题中的历史使用顺序：

1. 主编先按 `topic-planning` Skill 形成高咨询可能性的初步候选；
2. 读取 `_history-index.jsonl`，只按初步候选的客户、经营动作、决策问题、核心答案和服务机会检索可能重复项；
3. 按 `shared/rules/topic-memory-reading.md` 读取近期推荐与关联反馈，并检索相关旧推荐；不全量加载月度日志；
4. Metadata 已足以排除重复时，不读取历史正文；
5. 只有重复风险、关键条件或答案边界无法由 Metadata 判断时，才打开最少必要的相关历史正文；
6. 按客户决策问题和核心答案完成实质去重，同场景或同服务本身不是淘汰依据。

不得在候选形成前通过历史标题、主题、系列、关联内容或可延展选题寻找本轮切口。不得在每次选题时重新列举并解析全部历史 frontmatter，也不得固定读取最新 10 篇或执行“最新 10 篇 + 相关 10 篇”。

## 相关正文选择

历史索引较大时先在本地按初步候选的客户、经营动作、问题和答案筛选，只返回可能重复的命中元数据。无指定方向时也不得先取历史业务分布或历史样本来生成方向；方向应由账号定位下的客户问题和咨询可能性产生。

查重时优先选择与初步候选在以下字段高度相关的历史记录：

- `business_line`
- `theme`
- `audience`
- `pain_scene`
- `content_goal`
- 标题、客户场景、经营动作或服务机会的实质语义

默认不读取历史正文。只有重复风险无法可靠判断、关键条件或答案边界需要核对、同主题记录特别密集，或用户明确要求深度历史审查时才按需读取，并说明原因。不得为了寻找新切口而扩大正文读取。

## 候选与灵感

- Candidate Index 先用于计数和筛选；没有满足当前流程的候选时，不打开只有模板的 `待发布选题.md`。
- 候选状态只表示内容资格，不决定再次推荐；候选必须通过咨询可能性判断，不能因为已经入池而进入正式推荐。结合推荐记录排除已跳过及明确否定内容，旧题回归需要符合共享记录规则。需求依据和答案骨架从相关正文读取，不强制扩大索引。
- Idea Index 先用于筛选；只有识别出相关线索或进入灵感分析模式后，才读取具体灵感正文。
- 业务选题池只在初步方向命中具体候选或用户指定业务方向时按需打开，不扫描无关业务线，也不以池内既有分布替代获客判断。

## 派生资产

以下内容不是普通选题的默认数据源：

- `02-内容地图/**`
- `04-内容复盘/内容缺口分析.md`
- `04-内容复盘/重复选题检查.md`
- 月度复盘与其他覆盖统计

独立推荐记录中已经存在且与当前候选直接相关的效果摘要可以按需读取，不需要为此扫描完整复盘。缺失效果不得推断为零；自动历史延展不是实际客户反馈，不能单独构成新选题依据。

只有用户明确要求完整内容覆盖分析、业务结构分析、查看内容地图、月度复盘或派生资产维护时才读取。

## 事实优先级与失败处理

```text
历史 Markdown = 最终事实源
History Index = 当前机器检索层
候选/灵感 Index = 对应资产的机器检索层
内容地图、缺口、重复检查、复盘 = 派生辅助数据
```

Index 或派生资产与 Markdown 冲突时，以 Markdown 为准并重建对应 Index。Index 缺失时使用共享脚本从 Markdown 重建；无法可靠读取或重建时，明确报告阻塞，不输出正式选题。

历史内容不证明政策、税率、期限、处罚标准、平台规则或办理条件仍然有效。进入最终候选并把这些内容作为确定性事实或专业结论使用时，必须另行核验当前官方来源。历史内容中的匿名说法可以按 `shared/rules/acquisition-and-fact-framing.md` 保留为讨论型话题，但不得作为当前专业结论的依据。

## Same Session Snapshot

在同一连续任务中，未变的账号定位、三个 Index 与相关正文可复用。新增推荐或反馈后重新评估排除范围、去重与排序，不重复扫描未变索引；相关内容数据变化失效对应快照，账号切换丢弃整个账号快照。

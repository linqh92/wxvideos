# 历史内容库读取规则

## 动态位置

```text
内容库：accounts/{CURRENT_ACCOUNT}/内容库
历史事实源：01-历史内容/**/*.md
历史检索层：01-历史内容/_history-index.jsonl
候选检索层：03-选题规划/_candidate-index.jsonl
灵感检索层：03-选题规划/灵感库/_idea-index.jsonl
```

只允许读取根 `AGENTS.md` 已锁定的当前账号。

## Index First

普通选题按以下顺序读取：

1. 精简后的 `账号基本定位.md`；
2. `_history-index.jsonl`；
3. `_candidate-index.jsonl`；
4. `_idea-index.jsonl`；
5. 基于 metadata 形成约 8～10 个初步方向；
6. 只打开与候选高度相关的历史正文，正常综合控制在约 5～8 篇；
7. 完成实质去重和排序。

不得在每次选题时重新列举并解析全部历史 frontmatter，也不得固定读取最新 10 篇或执行“最新 10 篇 + 相关 10 篇”。

## 相关正文选择

优先选择与候选在以下字段高度相关的历史记录：

- `business_line`
- `theme`
- `audience`
- `pain_scene`
- `content_goal`
- 标题、客户场景、经营动作或服务机会的实质语义

正文读取量不是硬上限。只有重复风险无法可靠判断、同主题记录特别密集或用户明确要求深度历史审查时才适度增加，并说明原因。

## 候选与灵感

- Candidate Index 先用于计数和筛选；没有满足当前流程的候选时，不打开只有模板的 `待发布选题.md`。
- Idea Index 先用于筛选；只有识别出相关线索或进入灵感分析模式后，才读取具体灵感正文。
- 业务选题池只在 Index 命中具体候选或用户指定业务方向时按需打开，不扫描无关业务线。

## 派生资产

以下内容不是普通选题的默认数据源：

- `02-内容地图/**`
- `04-内容复盘/内容缺口分析.md`
- `04-内容复盘/重复选题检查.md`
- 月度复盘与其他覆盖统计

只有用户明确要求完整内容覆盖分析、业务结构分析、查看内容地图、月度复盘或派生资产维护时才读取。

## 事实优先级与失败处理

```text
历史 Markdown = 最终事实源
History Index = 当前机器检索层
候选/灵感 Index = 对应资产的机器检索层
内容地图、缺口、重复检查、复盘 = 派生辅助数据
```

Index 或派生资产与 Markdown 冲突时，以 Markdown 为准并重建对应 Index。Index 缺失时使用共享脚本从 Markdown 重建；无法可靠读取或重建时，明确报告阻塞，不输出正式选题。

历史内容不证明政策、税率、期限、处罚标准、平台规则或办理条件仍然有效。进入最终候选并把这些内容作为确定性事实或专业结论使用时，必须另行核验当前官方来源。历史内容中的匿名说法可以按 `shared/rules/acquisition-and-fact-framing.md` 保留为讨论型话题，但不得作为当前专业结论的依据。

## Same Session Snapshot

在同一连续任务中，若没有新增归档、灵感写入、候选修改或历史修改，可复用当前账号定位、三个 Index、相关正文和去重结果的快照。数据变化或账号切换后必须使快照失效。
